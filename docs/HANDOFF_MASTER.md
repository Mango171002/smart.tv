# IPTV International — Claude Code implementation brief

## 0. Source of truth and honesty
This repository includes the actual previously produced `index.html` prototype. It is a static, non-commercial design prototype, NOT a production-ready IPTV store. Keep all existing validated design concepts; do not assert that supplier rights, prices, channel lists, customer reviews, payment providers, countries, or activation APIs are verified. Brand name is **NOT DECIDED**. `GlobalTV+` is a temporary prototype placeholder and MUST be replaced through configuration before launch. Do not claim it is the selected brand.

## 1. Project goals
Build a premium international streaming/IPTV storefront for prospective customers in Europe, Canada, and the USA, subject to verified territorial redistribution rights. Core outcomes: clear offer discovery, accessible responsive layout, understandable pricing, smooth checkout, trustworthy support/onboarding, local language and currency, SEO and performance.

## 2. Validated design direction
- Dark Cinematic Premium, premium editorial style, mobile-first.
- Background palette: navy #080D18 / #0B1425; panel #101D32; gold accent #D9B76F; white #F7F8FB; muted #A7B5CA.
- Strong hero with cinema/streaming visual, single clear primary CTA, supporting secondary CTA.
- Professional typography, restrained gold accents, generous spacing, large legible buttons, subtle gradients, responsive cards, sticky header.
- Avoid deceptive badges, fabricated ratings/reviews, channel or studio logos without permission, and misleading unlimited-content claims.

## 3. Current prototype: what's actually implemented
The included `index.html` is self-contained HTML/CSS/JS, with:
1. Responsive sticky navigation and mobile menu.
2. Hero with streaming visual and primary CTAs.
3. Benefit strip.
4. Pricing selector: region (US, Canada, Europe), durations (1/3/6/12 months), simultaneous streams (1–4), illustrative pricing in USD/CAD/EUR.
5. Six illustrative content categories: Live TV, Movies, Series, Sports, Documentaries, Family.
6. Device compatibility section: Smart TV, streaming devices, mobile/tablet, computer.
7. Three-step How it Works.
8. FAQ and help CTA.
9. Three-step **simulated** checkout modal with review and demo-complete state.
10. Footer and explicit demo/legal disclaimers.
The prototype has NO backend, real orders, real payments, real activations, CRM, email, support integration, real catalog, analytics, or legal documents. Currency conversion factors and prices are illustrative only.

## 4. Suggested production information architecture
- Home: hero, value proposition, plans configurator, licensed categories, devices, setup steps, verified trust signals, FAQ, support CTA.
- Plans: detailed price matrix, regions, durations, concurrent streams, inclusions/exclusions, taxes and renewal policy.
- Devices & Setup: supported devices and app-specific guides only after technical verification.
- Coverage/Catalog: licensed content and geographic availability, managed per territory.
- Help Center: FAQ, contact, order status, device troubleshooting, refund process.
- Legal: Terms, Privacy, Cookies, Refunds/Cancellations, licensing and business identity.
- Checkout: secure server-side quote, customer information, tax computation, payment provider, consent, confirmation.
- Customer Area (phase 2): order history, invoices, subscriptions, support tickets.

## 5. Production architecture suggestion (not yet approved)
Next.js App Router + TypeScript + Tailwind + accessible component system; PostgreSQL/Supabase for customer/order data; server-side pricing and order validation; provider-hosted checkout; webhook verification; email provider; optional i18n (EN default, FR, other languages based on demand). Keep infrastructure modular. Do not choose a payment provider until underwriting and business eligibility are verified.

## 6. Critical product and data rules
- Configurable `brandName`, `domain`, `supportEmail`, `legalEntity`, `legalAddress`, `licensedTerritories`, `contentCatalog`, `supportedDevices`, `prices`, `taxRules`, `paymentMethods`, `refundPolicy`, `activationProvider`.
- Currency must use market-specific approved price tables; DO NOT use the demo FX multiplication as live prices.
- Plans keyed by duration and streams, and region/market; server computes totals; taxes disclosed before final confirmation.
- Checkout must never send credentials, M3U URLs, or sensitive activation secrets to the browser unnecessarily.
- Store only required customer data, protect secrets in environment variables, rate-limit endpoints, validate inputs, use CSRF protections where relevant, verify webhooks, idempotent fulfillment, auditable order states.
- Accessibility: keyboard navigable dialogs, focus trap/restore, labeled inputs, visible focus, WCAG AA contrast, reduced-motion support.
- SEO: unique titles/descriptions, metadata, canonical URLs, sitemap, robots, hreflang where applicable, schema only for genuine facts, performant Core Web Vitals.
- GDPR/ePrivacy and relevant local privacy/consumer obligations must be assessed by qualified counsel.

## 7. Blocking launch checklist
[ ] Verify written supplier authorization for redistribution and each territory, channels and VOD rights.
[ ] Verify right to use logos, posters, trademarks, and promotional content.
[ ] Confirm brand and domain, trademark clearance in EU/US/CA.
[ ] Confirm business entity, tax registration, payment processor eligibility, terms, privacy, refund/cancellation terms.
[ ] Confirm actual prices, devices, delivery SLA, support hours, trial policy (if any), renewal and cancellation behavior.
[ ] Integrate secure checkout and verified order fulfillment.
[ ] Test cross-device UX, payment edge cases, accessibility, security, privacy, and support processes.
